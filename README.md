# پورتفولیوی احمدرضا عبداللهی

وب‌سایتی فارسی و راست‌به‌چپ برای معرفی احمدرضا عبداللهی: حدود ۳ سال تمرین توسعهٔ Android، شروع یادگیری Swift و SwiftUI، و جست‌وجوی فرصت کارآموزی iOS.

سایت با HTML، CSS و JavaScript ساخته شده است. برای اجرا یا انتشار آن به نصب بسته، `npm`، فرایند build یا سرور اختصاصی نیاز ندارید.

## طراحی رابط

طراحی با الهام از [رابط وب‌سایت گردول](https://gordol.app/#pricing) تنظیم شده است: معرفی روی زمینهٔ سفید با تیتر بزرگ مشکی و منوی شناور شیشه‌ای؛ بخش پروژه‌ها روی زمینهٔ مشکی با تیتر سفید تا آبی روشن و سه کارت روشن با گوشه‌های گرد؛ و بخش تماس ساده با آیکون‌های GitHub، LinkedIn و ایمیل. پیش‌نمایش برنامه‌ها داخل تصویر ماکت واقعی‌تر آیفون قرار می‌گیرد. دو کارت Storybook و Onboarding فعلاً کاملاً تار و ناخوانا هستند و فقط عبارت «بزودی» روی آن‌ها دیده می‌شود.

حالت روشن و تیره، چیدمان واکنش‌گرا و راست‌به‌چپ، تصویر واقعی Dice Roller و کد ارسالی آن حفظ شده‌اند. فونت سایت مرجع Estedad است، اما این پورتفولیو از فونت محلی وزیرمتن (Vazirmatn) استفاده می‌کند و برای نمایش فونت به اینترنت وابسته نیست.

## شروع سریع

1. فایل ZIP را از حالت فشرده خارج کنید.
2. پوشهٔ `ahmadreza-abdollahi-portfolio` را باز کنید.
3. روی `index.html` دوبار کلیک کنید تا سایت در مرورگر باز شود.
4. برای تغییر اطلاعات و لینک‌ها، `site.config.js` را با یک ویرایشگر متن باز کنید.

بعد از ذخیرهٔ تغییرات، صفحهٔ مرورگر را تازه‌سازی کنید. تمام فایل‌ها و پوشهٔ `assets` باید کنار هم باقی بمانند.

## فایل‌های اصلی

```text
ahmadreza-abdollahi-portfolio/
├── index.html                 متن‌ها و ساختار صفحه
├── styles.css                 رنگ‌ها، اندازه‌ها و طراحی واکنش‌گرا
├── script.js                  رفتارهای صفحه و خواندن تنظیمات
├── site.config.js             نام، لینک‌ها و تصاویر پروژه‌ها
├── .nojekyll                  انتشار مستقیم فایل‌های استاتیک
├── README.md                  همین راهنما
└── assets/
    ├── licenses/              مجوز و منبع آیکون‌ها و ماکت آیفون
    ├── fonts/                 فونت محلی وزیرمتن و مجوز آن
    ├── mockups/               تصویر محلی iphone-16-pro-max.png
    └── screenshots/           تصویر واقعی Dice Roller و تصاویر پروژه‌ها
```

## شخصی‌سازی اطلاعات

فایل `site.config.js` تنظیمات را در `window.PORTFOLIO` نگه می‌دارد. نام کامل، اطلاعات تماس، تصویر واقعی Dice Roller و لینک [مخزن DiceRoller](https://github.com/aabdollahi725/DiceRoller) وارد شده‌اند. Storybook و Onboarding در وضعیت «بزودی» قرار دارند؛ لینک مخزن و تصاویر واقعی آن‌ها هنوز اضافه نشده‌اند.

| تنظیم | چه چیزی وارد کنید؟ |
| --- | --- |
| `name` | نام نمایشی؛ مقدار فعلی «احمدرضا عبداللهی» است |
| `github` | نشانی کامل پروفایل واقعی GitHub، با `https://` |
| `linkedin` | نشانی کامل پروفایل واقعی LinkedIn، با `https://` |
| `email` | نشانی ایمیل واقعی، بدون `mailto:` |
| `projects.dice.repo` | تنظیم شده روی `https://github.com/aabdollahi725/DiceRoller` |
| `projects.storybook.repo` | نشانی مخزن واقعی Storybook |
| `projects.onboarding.repo` | نشانی مخزن واقعی Onboarding |
| `projects.storybook.comingSoon` | مقدار `true` کارت را در وضعیت «بزودی» نگه می‌دارد؛ برای نمایش محتوا `false` بگذارید |
| `projects.onboarding.comingSoon` | همان تنظیم برای کارت Onboarding |

مقدارها را داخل علامت نقل‌قول قرار دهید و نام تنظیمات را تغییر ندهید. اگر لینک مخزن پروژه‌ای هنوز آماده نیست، مقدار `""` را نگه دارید؛ لینک کد آن پروژه نمایش داده نمی‌شود.

برای تغییر معرفی یا توضیح پروژه‌ها، متن مربوط را در `index.html` پیدا و ویرایش کنید. برای تغییر نام، عنوان تب مرورگر و توضیح کوتاه سایت را نیز در بخش `<head>` همین فایل بررسی کنید. سایت سه بخش معرفی، پروژه‌ها و تماس دارد و لوگوی شخصی ندارد. اطلاعات تماس برای اجرای بدون JavaScript در بخش تماسِ `index.html` نیز درج شده است؛ هنگام تغییر یا حذف اطلاعات تماس، آن بخش را هم هماهنگ کنید.

توضیح هر پروژه در `index.html` دربارهٔ عملکرد همان برنامه است. کارت‌ها پنجرهٔ «درباره تمرین» و برچسب‌های کپسولی ندارند. کد نمایش‌داده‌شده در بخش معرفی، کد ارسالی `ContentView.swift` پروژهٔ Dice Roller است و در همین فایل HTML قرار دارد. برای تغییر نام در حالتی که JavaScript غیرفعال است و برای موتورهای جست‌وجو، نام‌های اولیهٔ داخل `index.html` را نیز هماهنگ کنید.

حالت روشن و تیره از دکمهٔ بالای صفحه قابل انتخاب است. انتخاب کاربر فقط در همان مرورگر ذخیره می‌شود. اطلاعات تماس ارسال یا در سروری ذخیره نمی‌شود؛ دکمهٔ ایمیل، برنامهٔ ایمیل کاربر را باز می‌کند. پس از واردکردن ایمیل معتبر، دکمهٔ کپی آن نیز ظاهر می‌شود.

## افزودن اسکرین‌شات واقعی

فایل `assets/screenshots/dice-roller.png` همان تصویر واقعی ارسالی صاحب سایت است و بدون تغییر همراه پروژه قرار دارد. این تصویر در کارت Dice Roller و ماکت آیفونِ بخش معرفی استفاده می‌شود. قاب گوشی از یک فایل تصویری محلی ساخته شده است و هر سه کارت از همین ماکت استفاده می‌کنند. تصویر Dice Roller در بخش معرفی و کارت پروژه به‌صورت کامل و بدون برش نمایش داده می‌شود؛ محتوای دو کارتِ «بزودی» فعلاً زیر تاری قرار دارد.

1. از اجرای پروژهٔ خودتان در شبیه‌ساز یا دستگاه اسکرین‌شات بگیرید.
2. فایل را داخل `assets/screenshots` قرار دهید؛ مثلاً `dice-roller.png`.
3. تنظیمات همان پروژه را در `site.config.js` ویرایش کنید:

```js
dice: {
  repo: "https://github.com/aabdollahi725/DiceRoller",
  screenshot: "assets/screenshots/dice-roller.png",
  screenshotAlt: "برنامه Dice Roller با سه تاس و دکمه‌های افزودن و حذف تاس"
}
```

این نمونه فقط قسمت مربوط به `dice` را نشان می‌دهد؛ تنظیمات بقیهٔ پروژه‌ها را نگه دارید. لینک Dice Roller از قبل وارد شده است. برای پروژه‌های دیگر، مقدار `repo` را با لینک واقعی مخزن جایگزین کنید یا خالی بگذارید.

فایل‌های WebP، PNG یا JPG مناسب‌اند. نام فایل کوتاه و انگلیسی انتخاب کنید و بزرگی و کوچکی حروف را دقیقاً رعایت کنید. برای بارگذاری سریع‌تر، تصویر را متناسب با اندازهٔ نمایش آن کوچک کنید؛ عرض حدود ۸۰۰ پیکسل برای اغلب تصاویر کارت کافی است.

مسیر تصویر باید نسبی باشد: `assets/screenshots/dice-roller.png`؛ در ابتدای آن `/` نگذارید. این کار باعث می‌شود تصویر هم در اجرای محلی و هم در سایت پروژه‌ای GitHub Pages درست باز شود. `screenshotAlt` توضیح کوتاه و معناداری برای کاربران صفحه‌خوان است. اگر مسیر تصویر Dice Roller را عوض کردید، مسیر اولیهٔ همان تصویر در بخش معرفی و کارت پروژه در `index.html` را نیز هماهنگ کنید.

## آماده‌کردن کارت‌های «بزودی»

برای Storybook و Onboarding مقدار `comingSoon: true` فعال است. تمام محتوای هر کارت، از جمله تصویر، عنوان و توضیح، تار می‌ماند و عبارت «بزودی» روی آن نمایش داده می‌شود. این دو کارت از نظر رنگ و شکل با کارت Dice Roller یکسان‌اند.

وقتی پروژه‌ای آماده شد، تصویر واقعی و لینک مخزن همان پروژه را در `site.config.js` وارد کنید، توضیح آن را در `index.html` با عملکرد واقعی برنامه هماهنگ کنید و `comingSoon` را روی `false` بگذارید. بعد از ذخیره و تازه‌سازی صفحه، محتوای کارت نمایش داده می‌شود. `true` و `false` باید بدون علامت نقل‌قول نوشته شوند. طرح‌های نمونهٔ قبلی همچنان در فایل HTML وجود دارند؛ پیش از فعال‌کردن کارت، آن‌ها را با اسکرین‌شات واقعی جایگزین کنید. اگر نمایش بدون JavaScript هم باید هم‌زمان به‌روز شود، وضعیت اولیهٔ «بزودی» همان کارت را در HTML نیز هماهنگ کنید.

## محتوای پروژه‌ها را دقیق نگه دارید

Dice Roller به‌عنوان پروژه‌ای تمرینی نمایش داده می‌شود و دو کارت دیگر فعلاً «بزودی» هستند. پیش از نمایان‌کردن هر کارت، توضیح آن را با چیزی که واقعاً ساخته‌اید هماهنگ کنید.

- فقط قابلیت‌هایی را بنویسید که در پروژه وجود دارند.
- اگر تمرینی هنوز شروع یا تکمیل نشده، وضعیت واقعی آن را روشن بنویسید یا کارت را فعلاً حذف کنید.
- برای هر مخزن، README کوتاه، روش اجرا و اسکرین‌شات اضافه کنید.
- «حدود ۳ سال تمرین Android» را با «۳ سال سابقهٔ شغلی» جایگزین نکنید، مگر اینکه واقعاً سابقهٔ کاری شما باشد.
- مهارت‌های SwiftUI در حال یادگیری‌اند؛ درصد مهارت یا سابقهٔ حرفه‌ای تأییدنشده اضافه نکنید.

## انتشار رایگان در GitHub Pages

برای استفاده از GitHub Pages با حساب GitHub Free، مخزن سایت باید **Public** باشد. فایل `index.html` باید در ریشهٔ پوشه‌ای قرار بگیرد که برای انتشار انتخاب می‌کنید. فایل `.nojekyll` این پروژه را هم نگه دارید تا فایل‌ها مستقیماً منتشر شوند. [راهنمای رسمی ساخت سایت](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

برای حساب `aabdollahi725` دو انتخاب دارید. نشانی‌های زیر پس از ساخت مخزن و فعال‌کردن Pages در دسترس قرار می‌گیرند؛ این راهنما به معنی انتشار فعلی سایت نیست:

| نوع سایت | نام مخزن | نشانی نهایی |
| --- | --- | --- |
| سایت شخصی | `aabdollahi725.github.io` | `https://aabdollahi725.github.io/` |
| سایت پروژه‌ای | `portfolio` | `https://aabdollahi725.github.io/portfolio/` |

اگر از قبل سایت شخصی دارید، می‌توانید این پورتفولیو را در مخزن جداگانهٔ `portfolio` منتشر کنید. مسیرهای نسبی پروژه برای هر دو حالت آماده‌اند. [راهنمای نام‌گذاری سایت شخصی](https://docs.github.com/en/pages/quickstart)

### مراحل انتشار از داخل GitHub

1. وارد حساب `aabdollahi725` در GitHub شوید و یک مخزن جدید بسازید. برای سایت شخصی، نام را دقیقاً `aabdollahi725.github.io` بگذارید؛ اگر این مخزن از قبل برای سایت دیگری استفاده می‌شود، نام `portfolio` را انتخاب کنید. حالت **Public** را فعال کنید.
2. با **Add file → Upload files**، **محتویات داخل** پوشهٔ `ahmadreza-abdollahi-portfolio` را بارگذاری کنید. خود فایل ZIP یا پوشهٔ بیرونی را به‌عنوان تنها فایل مخزن نفرستید.
3. تغییرات را روی شاخهٔ `main` ذخیره کنید. در صفحهٔ اصلی مخزن باید `index.html`، `site.config.js` و پوشهٔ `assets` را مستقیم ببینید.
4. وارد **Settings → Pages** شوید.
5. در **Build and deployment → Source**، گزینهٔ **Deploy from a branch** را انتخاب کنید.
6. شاخه را روی **main** و پوشه را روی **/(root)** قرار دهید و **Save** را بزنید.
7. بعد از پایان انتشار، لینک **Visit site** را در همان صفحه باز کنید.

در این روش نیازی به نوشتن workflow یا تنظیم دستور build ندارید. با هر تغییر بعدی در شاخهٔ انتخاب‌شده، GitHub سایت را دوباره منتشر می‌کند. وضعیت انتشار و خطاهای احتمالی در بخش **Actions** مخزن دیده می‌شود. [راهنمای رسمی انتخاب منبع انتشار](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

انتشار تغییرات ممکن است تا حدود ۱۰ دقیقه طول بکشد. [راهنمای مشاهدهٔ سایت منتشرشده](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site#viewing-your-published-site)

فایل `.nojekyll` مخفی است. برای دیدن فایل‌های مخفی در Finder مک، کلیدهای `Command + Shift + .` را بزنید. پس از بارگذاری، وجود این فایل در مخزن را بررسی کنید.

## اگر چیزی درست نمایش داده نشد

| مشکل | بررسی کنید |
| --- | --- |
| خطای 404 | فایل `index.html` در ریشهٔ `main` باشد؛ منبع Pages روی `main / (root)` باشد؛ انتشار در Actions تمام شده باشد |
| ظاهر ساده یا تصاویر گمشده | همهٔ فایل‌ها و پوشهٔ `assets` آپلود شده باشند؛ مسیرها با `/` شروع نشوند |
| تصویر جدید دیده نمی‌شود | نام و پسوند دقیق فایل با `screenshot` یکی باشد؛ صفحه را تازه‌سازی کنید |
| کارت هنوز تار است و «بزودی» دارد | مقدار `comingSoon` همان پروژه را در `site.config.js` روی `false` بگذارید و صفحه را تازه‌سازی کنید |
| لینک کد نمایش داده نمی‌شود | مقدار `repo` مربوط در `site.config.js` خالی است؛ لینک کامل واقعی را وارد کنید |
| بعد از ویرایش، تنظیمات اعمال نمی‌شود | نقل‌قول‌ها، ویرگول‌ها و آکولادهای `site.config.js` را بررسی کنید |

این بسته وب‌سایت پورتفولیو و کد نمایشی `ContentView.swift` را شامل می‌شود؛ پروژهٔ کامل برنامه‌های SwiftUI در آن نیست. انتشار عمومی هنوز انجام نشده است و با مراحل بالا در حساب خودتان انجام می‌شود.

## فونت و وابستگی‌ها

سایت هیچ وابستگی اجرایی، CDN، ابزار تحلیل رفتار یا درخواست شبکهٔ خارجی ندارد. فونت [وزیرمتن](https://github.com/rastikerdar/vazirmatn) نسخهٔ `33.003` به‌صورت محلی همراه پروژه است و با مجوز SIL Open Font License استفاده می‌شود. فایل `assets/fonts/OFL.txt` و مشخصات منبع در همان پوشه را نگه دارید. ماکت آیفون یک فایل تصویری محلی است؛ طرح‌های نمونهٔ زیر تاریِ دو کارت دیگر با CSS ساخته شده‌اند و تصویر Dice Roller یک اسکرین‌شات واقعی است.

آیکون‌های GitHub، LinkedIn و ایمیل از [Bootstrap Icons](https://icons.getbootstrap.com/) با مجوز MIT استفاده می‌کنند. مجوز و منبع آن‌ها در `assets/licenses` قرار دارد.

تصویر ماکت iPhone 16 Pro Max از [WebMobileFirst](https://www.webmobilefirst.com/en/mockups/apple-iphone-16-pro-max-2024/) دریافت شده و به‌صورت محلی در `assets/mockups/iphone-16-pro-max.png` قرار دارد. این تصویر تولیدشده با هوش مصنوعی نیست. منبع و شرایط استفاده در `assets/licenses/iphone-mockup-source.md` ثبت شده است؛ این فایل را همراه پروژه نگه دارید.
